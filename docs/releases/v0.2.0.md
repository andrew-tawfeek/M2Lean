# M2Lean 0.2.0 release notes

M2Lean 0.2.0 is the first artifact release accompanying the preprint
*M2Lean: Certificate-Based Interoperability Between Macaulay2 and Lean 4*.
It is a research prototype with an intentionally narrow protocol and explicit
assurance levels.

## Highlights

- Protocol 0.2.0 for rational and prime fields, canonical sparse
  polynomials, ideals, matrices, graded modules, and seven claim kinds.
- Macaulay2 certificate production and in-session invocation of the Lean
  verifier.
- A standalone `m2lean-check` executable with structured diagnostics and
  provenance echoing.
- Kernel-checked soundness for identity, membership, span inclusion,
  chain-complex composition, and GRevLex Gröbner and non-membership claims.
- Twisted-cubic, Jacobian, graph-coloring, separability, finite-field, and
  commutative-algebra case studies.
- Deterministic replay of all 11 generated JSON documents and four generated
  Lean data modules before theorem builds.
- A release test matrix of 15 accepted and 20 deliberately invalid documents.

## Compatibility

Protocol 0.2.0 is not backward compatible with 0.1.0 Gröbner certificates
that omitted coprime-leading-monomial pairs. Regenerate those documents:
0.2.0 requires evidence for every pair of distinct basis elements.

The end-to-end release environment uses Macaulay2 1.24.11, Lean 4.32.0, and
mathlib commit `81a5d257c8e410db227a6665ed08f64fea08e997` on Debian 13. Macaulay2
package compatibility was additionally checked against official version
1.26.06 packages. Exact container, package, and artifact hashes are recorded
under `reproducibility/`.

## Verification

From a clean checkout:

```sh
bash scripts/test-all.sh
```

The command regenerates tracked artifacts, checks them against the committed
SHA-256 ledger, checks all valid and invalid documents with their diagnostic
classes, builds the theorem files, and runs the axiom audit.

## Known boundaries

- Lex Gröbner and graded-complex claims are executable-only (`checked`).
- Complex claims do not certify exactness, minimality, cokernels, or Betti
  tables.
- The live tactic supports only a small ground membership fragment.
- Public Macaulay2 collection and Reservoir distribution are follow-up steps;
  consumers should pin this Git tag or its full commit.
- Benchmarks are descriptive for the recorded machine and inputs. No scaling
  conclusion is claimed.

## Artifact identity

`reproducibility/manifest.json` is a static input to the release tag. Its
post-tag commit, archive, and benchmark fields remain null because updating
them would change the commit they identify.

After creating the annotated tag and permanent archive, run
`scripts/release-record.py` from the exact clean tag commit. It verifies that
the external benchmark was also recorded from that commit, hashes the static
manifest and optional release assets, and emits a record conforming to
`reproducibility/release-record.schema.json`. The benchmark and post-tag
record are attached to the GitHub release and archive; neither is committed
back into the tagged tree.
